# Markdown Cornell Notes 2.2.0

Write meeting notes in Markdown, fill in the topic, date, and attendees,
and click **Render** to get a printable Cornell-style PDF, with the notes
panel, cue column, and summary band laid out for you.

Version 2.2 gives the PDF preview a memory and a connection to the editor,
makes deleting recoverable, and adds a handful of smaller conveniences.

## What's new

- **A preview that keeps its place.** The PDF preview is now built on
  PDF.js. After a Render it stays at the zoom and scroll position it had,
  instead of jumping back to the top of page 1. Its controls (page, zoom,
  fit page, fit width) are in the pane's header.
- **Editor and preview follow each other.** When the cursor rests on a
  line, the preview scrolls to that text in the PDF and marks it;
  double-click text in the preview to jump to its line in the editor. The
  match is by text, so it's approximate: headings and ordinary sentences
  work well, tables and math may not. *View > Sync Preview with Editor*
  turns the following off.
- **Auto-render.** With *View > Auto-Render as You Type* on, the PDF
  rebuilds itself a moment after you stop typing. Off by default.
- **Find in the PDF**, and a button to open the PDF in your system's own
  viewer — which is how to print it.
- **Deleting goes to the trash.** Deleted notes and assets are moved to
  the system's trash rather than removed for good (where the system has a
  trash for that location).
- **Links follow renamed assets.** Renaming or moving an asset offers to
  update the links to it across the project's notes.
- **A starting template for new notes**, showing a cue note and a summary
  note.
- **Help menu** with a list of keyboard shortcuts (F1).
- **A menu entry for the .deb and RPM.** Installed from a package, the
  editor now appears in the application menu, and opens the project you
  used last.

Version 2.1 added find and replace in the editor, renaming notes and asset
files, *File > New Project*, and *File > Open Recent*.

## Linux AppImage

Needs a 64-bit Intel or AMD PC and a distribution with glibc 2.34 or
later: Ubuntu 22.04, Debian 12, Fedora 35, or newer.

```sh
chmod +x Markdown-Cornell-Notes-2.2.0-x86_64.AppImage
./Markdown-Cornell-Notes-2.2.0-x86_64.AppImage
```

If you have an earlier 2.x AppImage, an update tool such as
AppImageUpdate or Gear Lever can fetch this version; or download it and
delete the old file. The first time the app opens it creates a **Cornell
Notes** folder in **Documents** with example notes; if you already have
one, it opens that as you left it.

If it doesn't start:

- **An error about `libxcb-cursor`** (X11 desktops):
  `sudo apt install libxcb-cursor0` or `sudo dnf install xcb-util-cursor`.
- **An error mentioning the sandbox** (Ubuntu 24.04 and later): start it
  with `--no-sandbox`.

## .deb and RPM

```sh
sudo apt install ./markdown-cornell-notes_2.2.0.deb                    # Debian 13+
sudo dnf install ./markdown-cornell-notes-2.2.0-1.fc44.noarch.rpm      # Fedora
```

Then start **Markdown Cornell Notes** from the application menu, or use
the command line in a project directory:

```sh
mkdir ~/notes && cd ~/notes
markdown-cornell-notes init
markdown-cornell-notes build      # or: markdown-cornell-notes app
```

The .deb was tested on Debian 13 and the RPM on Fedora 44. On Ubuntu 24.04
the command-line build should work, but its PySide6 is older than the
editor needs. Neither package is signed, and installed from a file like
this they don't update themselves.

## macOS and Windows — test builds

**Neither of these has been run on its own system yet.** They're
assembled and checked on Linux only, and they aren't signed in the way
macOS and Windows expect. If you try one, please
[report what happens](https://github.com/forloop11/markdown-cornell-notes/issues),
whether it works or not.

**macOS** (`Markdown-Cornell-Notes-2.2.0-arm64-mac.zip`, 526 MB; Apple
silicon, macOS 14 or later): unzip it, drag **Markdown Cornell Notes**
into **Applications**, and open it. macOS blocks it the first time,
because it isn't notarized: click **Done**, then go to **System Settings >
Privacy & Security**, find the message about Markdown Cornell Notes, and
click **Open Anyway**. If macOS says the app "is damaged", run this in
Terminal and open it again:

```sh
xattr -dr com.apple.quarantine "/Applications/Markdown Cornell Notes.app"
```

The menu bar may name the app "Python".

**Windows** (`Markdown-Cornell-Notes-Setup-2.2.0.exe`, 271 MB): if an
earlier version is installed, uninstall it first (**Settings > Apps**;
your notes aren't affected). Run the installer; when Windows shows
"Windows protected your PC", click **More info**, then **Run anyway**. It
installs for your user account only. The app has no `.exe` of its own, so
the taskbar may show it as "Python". If it doesn't start, running this in
Command Prompt shows why:

```bat
"%LOCALAPPDATA%\Programs\Markdown Cornell Notes\resources\python\python.exe" "%LOCALAPPDATA%\Programs\Markdown Cornell Notes\resources\pipeline\app\main.py"
```

## Known issues

- **The macOS and Windows builds are untested** (see above).

- **The editor/preview sync is approximate** (see above), and finds
  nothing for text changed since the last Render.
- **The preview has no Print button**; open the PDF in your system's
  viewer to print.
- **Spellcheck is US English only** in the AppImage, with no "add to
  dictionary"; the .deb and RPM include no dictionary.
- **Only files can be moved by dragging** in the assets explorer, not
  folders.
- **x86_64 only**, and the AppImage is a large download (about 335 MB),
  mostly Qt and the bundled LaTeX and pandoc.

If something doesn't work, please
[open an issue](https://github.com/forloop11/markdown-cornell-notes/issues),
and include the **Build log** text if Render failed.
